# Ранковий випуск: інструкція для хмарного завдання

Ти щоранку наповнюєш додаток «Ранкове читання» (файл `articles.json` у цьому репозиторії).
Користувач погано читає англійською: він читає статтю ПРЯМО В ДОДАТКУ — українською, з картинкою.
Тому кожна стаття має містити повноцінний переказ українською, а не лише короткий опис.

## Кроки

1. Прочитай `topics.json`: теми, ліміти, мови, джерела.
2. Для кожної теми знайди в інтернеті свіжі статті й дописи з блогів, опубліковані за останні 24–48 годин.
   - Якщо в темі є `sources`, спершу перевір ці сайти (офіційні блоги), потім шукай деінде.
   - Якщо в темі є `favoriteTeam`, щонайменше половина статей теми — про цю команду.
   - Пропусти статті, чиї `url` вже є в `articles.json`.
   - Дотримуйся розділу «Відбір» нижче.
3. Відкрий кожну обрану статтю через WebFetch і попроси: зміст статті, дату публікації та головну картинку
   (`og:image` / `twitter:image`, абсолютний https-URL).
   - Якщо WebFetch не може відкрити сайт (`ENOTFOUND` чи інша мережева помилка), НЕ зупиняйся і не повторюй спроби
     для цього сайту. Збери факти через WebSearch (кілька запитів за назвою; режим `extended` для свіжості),
     постав `image: null`, `verified: false`. Пиши лише те, що підтверджують результати пошуку.
4. Для кожної статті склади об'єкт (усі тексти — природною українською, СВОЇМИ СЛОВАМИ: це переказ,
   а не дослівний переклад; без довгих цитат, максимум одна коротка цитата до 15 слів):
   ```json
   {
     "title": "точний заголовок українською",
     "url": "https://…", "source": "домен", "topic": "назва теми з topics.json", "lang": "мова оригіналу (uk/en/it…)",
     "image": "https://… або null",
     "summary": "2 речення для картки",
     "lead": "одне сильне речення — суть",
     "keyPoints": ["3–4 короткі тези"],
     "body": ["3–5 абзаців по 2–4 речення: що сталося, контекст, деталі, цифри"],
     "whyItMatters": "1–2 речення, чому це варто знати",
     "readMinutes": 2,
     "verified": true
   }
   ```
   Нічого не вигадуй понад те, що є в джерелах.
5. Додай на ПОЧАТОК масиву `days` новий день `{ "date": "РРРР-ММ-ДД", "articles": [ … ] }` (дата за Києвом;
   якщо такий день уже є — допиши в нього). Онови `updated` (ISO-час).
6. Очищення:
   - залиш у `days` лише останні `keepDays` днів (за `date`), старіші видали повністю;
   - у кожній темі в усьому файлі має бути не більше `maxPerTopicTotal` статей: якщо більше, видаляй найстаріші статті цієї теми;
   - дні, що лишилися без статей, видали.
7. Перевір, що `articles.json` — валідний JSON, зроби коміт `Ранковий випуск РРРР-ММ-ДД`,
   виконай `git pull --rebase origin main` і запуш у гілку `main`.

## Відбір: якість понад кількість

Користувач не хоче засмічення. `perTopic` — це МАКСИМУМ на день, а не норма: краще 0 статей, ніж прохідна.
Додавай статтю лише якщо вона справді варта уваги:
- першоджерело (офіційний блог компанії, наукове видання, команда/ліга) або серйозне видання з власним матеріалом;
- справді нове й значуще: реліз, відкриття, важливий результат, суттєва новина, корисний практичний урок;
- НЕ брати: передруки й агрегатори, клікбейт, SEO-статті, «топ-10», чутки без джерела, рекламу, біржові прогнози;
- одна новина — одна стаття: не додавай кілька статей про ту саму подію (і перевір, чи її вже немає у файлі).
